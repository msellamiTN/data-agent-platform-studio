# Architecture — Independent Data Agent Platform Studio

## Product boundary

The Studio is **vendor-independent and self-contained**. The only runtime model is a small Hugging Face model executed locally through Transformers on the Colab GPU. CrewAI orchestrates two specialized agents. There are no external hosted-agent integrations or vendor-agent API calls.

The architecture follows common data-agent capabilities as local core functions: data preparation, shared metadata/context, business-question understanding, schema grounding, SQL generation, controlled tool execution, result visualization and traceability.

## One shared pipeline

~~~mermaid
flowchart LR
    SRC[CSV / File] --> DE[Data Engineering Agent]
    DE --> T1[Fixed Python ETL tool]
    T1 --> BR[Bronze source copy]
    BR --> CL[Profile / Clean / Validate]
    CL --> SI[Silver cleaned data]
    SI --> GO[Gold SQLite warehouse]
    GO --> MC[Manifest + Quality + Semantic Catalog]
    MC --> DA[Data Analysis Agent]
    DA --> SC[Schema inspection tool]
    SC --> LLM[Local Qwen model via CrewAI]
    LLM --> GEN[Generate SELECT]
    GEN --> SQL[Read-only SQL tool]
    SQL --> OUT[DataFrame / Chart / Explanation]
~~~

## Two user experiences

### 1. Data Engineering Agent

User controls:
- source CSV upload or built-in Retail Sales example;
- trim text fields;
- remove exact duplicates;
- remove fully empty rows;
- optional dataset/business description.

The CrewAI agent calls one bounded pipeline tool. Python executes the transformations and publishes the shared artifacts. The LLM summarizes only the tool's returned report.

### 2. Data Analysis Agent

The Data Analysis UI has no source upload. It consumes the active pipeline generated by the first scenario.

Mandatory flow:
1. Read the active manifest.
2. Inspect the actual Gold table schema and sample rows.
3. Read column profile and semantic catalog.
4. Interpret the business question in the supplied business context.
5. Generate a single SELECT query against `silver_data`.
6. Call the read-only SQL tool.
7. Summarize and visualize only the returned rows.

If the small model does not complete its tool call, a deterministic fallback query is run and the UI labels the fallback mode.

## Shared pipeline contract

The active run is stored under `workspace/pipeline/current/`:

~~~text
workspace/pipeline/current/
├── bronze/
│   └── source.csv
├── silver/
│   └── cleaned.csv
├── gold/
│   └── warehouse.sqlite
├── metadata/
│   └── quality_report.json
└── manifest.json
~~~

Gold SQLite:
- `silver_data` is the canonical analysis table.
- `staging_upload` is retained as a teaching/compatibility alias.

The manifest records:
- pipeline ID and dataset name;
- status and UTC creation time;
- Bronze/Silver/Gold artifact paths;
- row counts and duplicate-removal counts;
- null counts before and after;
- per-column data type, null count, distinct count and sample values;
- candidate dimensions, measures and date columns;
- optional user-provided business context.

This manifest is the shared contract between the two agents. Both scenarios run against the same active dataset, not separate uploads.

## Local agent runtime

- **Orchestration:** CrewAI.
- **Model:** Qwen/Qwen2.5-1.5B-Instruct from Hugging Face.
- **Inference:** Transformers with automatic device placement and FP16 when CUDA is available.
- **Runtime target:** Google Colab GPU, T4 when available.
- **UI:** Gradio Blocks with two separate scenario tabs.

The model adapter implements CrewAI's local LLM interface. It does not call a hosted model API. The same model instance is cached and shared by the two agents in a Colab process.

## Core capabilities

| Capability | Local component |
|---|---|
| Ingestion | Gradio CSV upload |
| Data quality | Pandas profile and cleaning |
| Transformation | Fixed ETL Python function |
| Data organization | Bronze / Silver / Gold artifact folders |
| Metadata | Pipeline manifest and column profile |
| Semantic context | Dimension/measure/date candidates + user business description |
| Agent planning | CrewAI roles, goals, tasks and tools |
| NL-to-SQL | Data Analysis Agent over inspected schema |
| Tool safety | Explicit read-only SQLite query tool |
| Visualization | DataFrame and Plotly |
| Traceability | Pipeline ID, quality report and artifact paths |

## SQL safety

The independent Data Analysis tool:
- accepts one statement beginning with SELECT or WITH;
- rejects comments and multiple statements;
- opens the SQLite database using read-only URI mode;
- applies a SQLite authorizer permitting read/select/function operations only;
- caps result rows at 100;
- verifies the database path is inside the application workspace.

The UI does not expose shell execution, arbitrary Python execution, database writes or credentials to the agents.

## Colab execution

1. Allocate a GPU runtime in Colab (T4 when available).
2. Install requirements.
3. Clone the development branch.
4. Launch Gradio.
5. Run Data Engineering first.
6. Run Data Analysis against the active manifest.

A Gradio share URL is public to anyone who obtains it. Use synthetic data in this training prototype.

## Scope and non-goals

This iteration does not provide:
- cloud data publishing or replication;
- external agent-provider connections;
- production multi-user isolation;
- durable storage across Colab runtime shutdown;
- production-grade semantic modeling or a full business glossary.

Those are separate platform capabilities that require their own specification and acceptance criteria. The current prototype focuses on a correct, inspectable, independent pipeline-and-agent loop.
